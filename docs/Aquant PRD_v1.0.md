## 0. 本修正版说明与冲突处理

本文件为《Aquant需求文档_v1.1.md》的自选生命周期口径修正版。修订依据为《自选生命周期管理_PRD_1.0.md》。

### 0.1 修订优先级

当本文原 v1.1 内容与自选生命周期管理 PRD 1.0 不一致时，以本修正版为准。核心原则如下：

1. 股票加入自选时必须确认交易系统。
2. 系统默认选中推荐交易系统，用户可直接修改，无需填写修改原因。
3. 观察策略、买入信号规则、买点确认方法、止损策略、止盈策略、卖出信号规则均由交易系统限定，加入自选时不再要求用户填写。
4. 观察池股票根据所属交易系统自动生成买入信号。
5. 买入信号生成后，系统继续自动判断买点确认方法是否满足。
6. 买点满足后，系统提醒用户人工确认买入。
7. 用户确认买入时必须确认止损位，目标价非必填。
8. 只有用户人工确认买入后，股票才进入交易页的“交易中”。
9. 用户放弃本次机会后，股票回到观察中，但本次已放弃信号不得重复生成。
10. MVP 阶段只支持全部卖出，不支持部分卖出。

### 0.2 已统一的不一致点

| 原 v1.1 口径 | 修正后口径 |
|---|---|
| 自选生命周期包含候选来源、初筛入池、重点观察、计划交易等较复杂状态 | 统一为市场候选、观察中、买入信号已生成、等待买点确认、买入待确认、交易中、卖出信号待处理、已卖出、待复盘等状态 |
| 今日交易计划是买入链路中的核心前置步骤 | 当前自选生命周期 PRD 1.0 中不再把今日计划作为买入必经状态；日计划保留在复盘/计划模块中 |
| 用户收到买入信号后可确认关注、确认交易、标记误报 | 系统先自动识别买入信号和买点；用户仅在买点满足后的“确认买入”环节做人工决策 |
| 买入前需要人工确认买入信号与买点 | 买入信号和买点确认由系统按交易系统规则自动判断 |
| 交易状态包含部分卖出 | MVP 只支持全部卖出 |
| H5 页面包含市场、自选、信号、交易、复盘等分散入口 | 底部导航统一为市场、自选、交易、复盘；自选内含观察/信号 |

### 0.3 暂不在本次修订中展开的内容

三套交易系统的具体规则细节将在下一阶段单独分析，包括：平台突破体系、上涨趋势体系、追涨接力体系。本文只保留交易系统能力边界和生命周期接口，不展开每套系统的完整指标参数。

## 1. 项目背景

A 股市场交易节奏快、题材轮动频繁、个股分化明显，普通投资者在实际交易中经常面临以下问题：

1. 无法快速判断当前市场是否适合交易。
2. 热门板块和热门个股信息来源分散，缺少统一筛选标准。
3. 自选股管理依赖人工记录，难以及时剔除失效标的。
4. 买卖点判断过度依赖主观经验，缺少规则化、可复盘的信号体系。
5. 交易后缺少系统复盘，无法判断是策略问题、市场问题还是执行问题。
6. 移动端查看行情和信号不够轻量，盘中提醒不够及时。

因此，Aquant 需要从简单的“行情展示工具”升级为一套完整的“市场状态判断 + 主线板块识别 + 个股候选池管理 + 交易信号分级 + 风控提醒 + 交易复盘”的闭环系统。

## 2. 产品定位

Aquant 是一套面向 A 股短线、波段交易场景的智能化市场监测与交易辅助系统。

系统通过多源行情数据、热门题材数据、涨停股数据、技术指标、市场情绪指标和交易复盘数据，为用户提供：

1. A 股市场整体状态监测。
2. 热门板块与热门个股识别。
3. 个性化自选股池动态管理。
4. 买入、卖出、风险信号分级提醒。
5. 人工确认后的交易记录管理。
6. 每周交易复盘与策略有效性分析。
7. 轻量化移动端 H5 展示。

系统不以“预测每只股票涨跌”为目标，而是帮助用户：

1. 判断今天是否适合交易。
2. 判断当前市场主线在哪里。
3. 判断哪些个股值得进入观察池。
4. 判断某个信号是真机会还是诱多。
5. 判断买入后什么时候该止损、止盈或退出。
6. 通过复盘持续修正策略和交易行为。

## 3. 产品核心原则

### 3.1 五层决策原则

所有买入信号必须经过以下五层校验：

```text
市场环境 → 板块强度 → 个股状态 → 技术触发 → 风险过滤
```

任何单一技术指标不得直接作为最终买入依据。

### 3.2 先过滤，再交易

系统的第一目标不是发现更多机会，而是过滤低质量机会。  
宁可少推信号，也不能在退潮期、高风险个股、高位出货阶段频繁推送买入提示。

### 3.3 信号必须可验证

每一个信号都必须记录：

1. 信号触发时间。
2. 信号所属策略。
3. 触发时市场环境。
4. 触发时板块状态。
5. 触发时个股价格、成交量、技术指标。
6. 后续 1/3/5/10 个交易日表现。
7. 是否被人工确认交易。
8. 最终盈亏结果。
9. 成功或失败原因。

### 3.4 风控优先于收益

系统应优先提醒以下风险：

1. 市场退潮。
2. 板块失效。
3. 个股高位放量。
4. 突破失败。
5. 跌破买入逻辑。
6. 连续亏损。
7. 计划外交易。

### 3.5 人工确认，不自动交易

MVP 阶段仅提供辅助决策与提醒，不提供自动下单。  
所有买入、卖出操作由用户最终确认。

## 4. 用户角色与使用场景

### 4.1 目标用户

1. 关注 A 股短线、波段机会的个人投资者。
2. 希望通过数据和规则提升交易纪律的用户。
3. 需要移动端实时查看自选股、信号和复盘结果的用户。
4. 希望构建个人交易系统而不是依赖主观感觉的用户。

### 4.2 核心使用场景

#### 场景一：开盘前查看市场与候选股

用户打开 H5 首页，查看：

1. 昨日市场温度。
2. 当前热门板块。
3. 昨日涨停股表现。
4. 今日重点观察股。
5. 风险提示。

#### 场景二：盘中接收自选信号与买入待确认提醒

系统扫描自选池个股，并按该股票所属交易系统自动识别买入信号和买点确认状态。

当买入信号已生成但买点未满足时，股票只在自选-信号中展示；当买点确认方法满足后，系统推送买入待确认提醒。提醒内容包括：

1. 个股名称和代码。
2. 所属板块。
3. 所属交易系统。
4. 买入信号类型。
5. 买点确认结果。
6. 风险点。
7. 建议止损位和信号失效条件。

#### 场景三：用户确认买入

用户只在“买入待确认”状态下点击“确认买入”，并填写或确认：

1. 买入价格。
2. 买入数量。
3. 仓位比例。
4. 止损位，必填。
5. 目标价，非必填。
6. 买入理由。
7. 交易备注。

确认买入后，股票才进入交易页的“交易中”。

#### 场景四：盘中触发卖出或风险信号

系统持续跟踪已确认交易的个股，若出现卖出信号或风险信号，推送提醒。

#### 场景五：周末复盘

系统自动生成周报：

1. 本周交易次数。
2. 胜率。
3. 盈亏比。
4. 最大回撤。
5. 最佳交易。
6. 最差交易。
7. 信号有效性。
8. 失败原因分布。
9. 下周改进建议。

# 7. 市场行情模块

## 7.1 基础行情数据采集

系统每日自动采集全 A 股市场核心行情数据。

### 7.1.1 采集字段

| 字段 | 说明 |
|---|---|
| trade_date | 交易日期 |
| sh_index | 上证指数 |
| sz_index | 深证成指 |
| cyb_index | 创业板指 |
| total_amount | 全市场成交额 |
| up_count | 上涨家数 |
| down_count | 下跌家数 |
| flat_count | 平盘家数 |
| up_ratio | 上涨率 |
| limit_up_count | 涨停家数 |
| limit_down_count | 跌停家数 |
| broken_limit_count | 炸板家数 |
| broken_limit_ratio | 炸板率 |
| max_continue_board | 最高连板数 |
| yesterday_limit_avg_return | 昨日涨停今日平均收益 |
| north_money | 北向资金，若数据源支持 |
| market_comment | 系统生成市场简评 |

### 7.1.2 更新频率

| 类型 | 频率 |
|---|---|
| 盘中行情 | 1 分钟级或数据源允许的最高频率 |
| 市场汇总 | 每 5 分钟刷新一次 |
| 日终快照 | 每个交易日 18:00 自动生成 |
| 历史回溯 | 支持按日期查询 |

---

## 7.2 市场温度评分 Market Score

系统需要根据市场整体表现生成 0-100 分的市场温度评分。

### 7.2.1 评分维度

| 维度 | 权重 | 说明 |
|---|---:|---|
| 指数表现 | 20% | 上证、深成指、创业板涨跌幅及趋势 |
| 市场宽度 | 20% | 上涨率、下跌率 |
| 涨停情绪 | 20% | 涨停数、连板高度、晋级率 |
| 风险扩散 | 20% | 跌停数、炸板率、亏钱效应 |
| 成交活跃度 | 20% | 全市场成交额、量能变化 |

### 7.2.2 市场状态分类

| 分数区间 | 状态 | 交易建议 |
|---|---|---|
| 80-100 | 强势 | 可积极跟踪主线核心股 |
| 65-79 | 修复 | 可低仓位参与强势板块 |
| 50-64 | 震荡 | 只做高质量信号 |
| 30-49 | 退潮 | 禁止追高，优先卖出与风控 |
| 0-29 | 冰点 | 停止买入，只观察 |

### 7.2.3 市场状态对信号的影响

| 市场状态 | 信号处理 |
|---|---|
| 强势 | S/A/B 信号均可推送 |
| 修复 | 只推送 S/A 信号 |
| 震荡 | 只推送 S 级信号，A 级降为观察 |
| 退潮 | 禁止买入信号，仅推风险提醒 |
| 冰点 | 停止买入信号扫描 |

# 8. 热门板块模块

## 8.1 热门板块 TOP3

系统每日自动识别市场热门板块 TOP3。

### 8.1.1 数据来源

可接入多个数据源：

1. 行情接口板块涨跌幅。
2. 资金流向数据。
3. 涨停股所属概念统计。
4. 新闻题材数据。
5. 财联社、同花顺、东方财富、雪球等热度榜单。

### 8.1.2 板块评分 Sector Score

| 维度 | 权重 | 说明 |
|---|---:|---|
| 板块涨幅 | 20% | 当日涨幅、3 日涨幅、5 日涨幅 |
| 涨停数量 | 20% | 板块内涨停股数量 |
| 龙头高度 | 15% | 板块最高连板数 |
| 资金强度 | 15% | 成交额变化、资金净流入 |
| 持续性 | 15% | 连续上榜天数 |
| 热度扩散 | 15% | 跟涨个股数量、媒体热度 |

### 8.1.3 板块类型识别

| 类型 | 识别规则 | 系统处理 |
|---|---|---|
| 主线板块 | 连续多日强势，板块内多股联动 | 重点展示，允许相关个股入池 |
| 轮动板块 | 当日强势但持续性不足 | 仅观察，不直接追高 |
| 一日游板块 | 单日冲高，次日无延续 | 降权 |
| 退潮板块 | 龙头断板、板块回落、亏钱效应扩散 | 禁止新入池 |

### 8.1.4 页面展示

热门板块 TOP3 需要展示：

1. 板块名称。
2. 板块涨幅。
3. 板块强度评分。
4. 涨停股数量。
5. 龙头股。
6. 入榜原因。
7. 持续性判断。
8. 风险提示。
9. 板块内重点关注个股。

# 9. 热门个股模块

## 9.1 热门股 TOP10

系统每日对接 3 个及以上 A 股主流热榜平台，生成综合热门股 TOP10。

### 9.1.1 数据来源

MVP 可先接入：

1. 财联社热榜。
2. 淘股吧热榜。
3. 其他主流热榜或行情平台。

后续可扩展：

1. 东方财富。
2. 同花顺。
3. 雪球。
4. 证券新闻平台。
5. 社交讨论热度源。

### 9.1.2 多平台排名计分规则

每个平台取前 20 名。  
前 20 名分别按照质数倒序赋分：

| 排名 | 分数 |
|---:|---:|
| 1 | 71 |
| 2 | 67 |
| 3 | 61 |
| 4 | 59 |
| 5 | 53 |
| 6 | 47 |
| 7 | 43 |
| 8 | 41 |
| 9 | 37 |
| 10 | 31 |
| 11 | 29 |
| 12 | 23 |
| 13 | 19 |
| 14 | 17 |
| 15 | 13 |
| 16 | 11 |
| 17 | 7 |
| 18 | 5 |
| 19 | 3 |
| 20 | 2 |

综合得分：

```text
热门股综合得分 = 平台 A 分数 + 平台 B 分数 + 平台 C 分数 + 多平台共振加分 - 风险扣分
```

### 9.1.3 共振加分

| 条件 | 加分 |
|---|---:|
| 同时进入 3 个平台前 20 | +15 |
| 同时进入 2 个平台前 20 | +8 |
| 属于当日主线板块 | +10 |
| 属于涨停股 | +8 |
| 属于连板股 | +10 |

### 9.1.4 风险扣分

| 条件 | 扣分 |
|---|---:|
| 30 日内出现日线顶背离 | -20 |
| 高位放量长上影 | -20 |
| 近 5 日涨幅过大且无充分换手 | -15 |
| 所属板块退潮 | -20 |
| 跌破关键均线 | -10 |
| 出现重大负面公告 | -50 |
| ST、退市风险、严重监管风险 | 直接排除 |

### 9.1.5 输出字段

热门股 TOP10 展示：

1. 排名。
2. 股票名称。
3. 股票代码。
4. 所属板块。
5. 当日涨幅。
6. 综合热度分。
7. 各平台排名。
8. 入榜原因。
9. 风险标签。
10. 是否可加入自选。
11. 系统推荐交易系统。
12. 雪球链接。

雪球链接格式：

```text
https://xueqiu.com/S/{stock_code}
```

# 11. 自选池管理模块（自选生命周期修正版）

## 11.1 自选池定位

自选池不是普通收藏夹，而是一个短线交易候选漏斗。股票从市场页热榜、涨停榜进入自选后，必须绑定明确的交易系统，并在该交易系统的规则约束下完成从观察、信号、买入、交易中、卖出到复盘的完整生命周期。

本模块不直接展开三套交易系统的具体参数。平台突破、上涨趋势、追涨接力的细节将在下一阶段单独定义。

## 11.2 加入自选强制规则

1. 加入自选必须确认交易系统。
2. 系统默认选中推荐交易系统，用户可直接修改，无需填写修改原因。
3. 可选交易系统包括：平台突破、上涨趋势、追涨接力。
4. 观察策略、买入信号规则、买点确认方法、止损策略、止盈策略、卖出信号规则均由交易系统限定。
5. 用户在加入自选时不需要填写上述交易系统规则。

## 11.3 自选生命周期状态

| 状态 | 含义 | 所在页面 | 是否代表真实交易 |
|---|---|---|---|
| 市场候选 | 股票出现在热榜、涨停榜，尚未加入自选 | 市场 | 否 |
| 观察中 | 已加入自选，已确认交易系统 | 自选-观察 | 否 |
| 买入信号已生成 | 系统根据交易系统规则识别出买入信号 | 自选-信号 | 否 |
| 等待买点确认 | 买入信号已生成，但买点确认方法尚未满足 | 自选-信号 | 否 |
| 买入待确认 | 系统判断买点确认方法已满足，提醒用户买入 | 自选-信号 / 交易提醒入口 | 否 |
| 交易中 | 用户人工确认买入，已记录实际交易 | 交易 | 是 |
| 卖出信号待处理 | 系统触发卖出信号，等待用户确认卖出 | 交易 | 是 |
| 卖出延后处理 | 用户选择暂不处理卖出提醒 | 交易 | 是 |
| 已卖出 | 用户确认全部卖出 | 交易 / 复盘 | 已结束 |
| 待复盘 | 已卖出但尚未完成复盘 | 复盘 | 已结束 |
| 已归档 | 生命周期结束，进入历史归档 | 复盘 / 归档 | 已结束 |
| 已失效 | 观察逻辑失效，退出观察 | 自选 | 否 |
| 黑名单 | 禁止再次自动加入或推荐进入自选 | 自选 / 后台 | 否 |

## 11.4 主状态流转

```text
市场候选
  ↓ 加入自选并确认交易系统
观察中
  ↓ 系统识别买入信号
买入信号已生成
  ↓ 系统判断买点确认方法
等待买点确认
  ↓ 买点确认方法满足
买入待确认
  ↓ 用户人工确认买入并确认止损位
交易中
  ↓ 系统触发卖出信号
卖出信号待处理
  ↓ 用户确认全部卖出
已卖出
  ↓ 系统生成复盘任务
待复盘
  ↓ 用户提交复盘
已归档 / 重新观察 / 黑名单
```

## 11.5 异常状态流转

```text
观察中 → 已失效
观察中 → 移除自选
买入信号已生成 → 放弃本次机会 → 观察中
等待买点确认 → 放弃本次机会 → 观察中
买入待确认 → 放弃本次机会 → 观察中
卖出信号待处理 → 卖出延后处理
卖出延后处理 → 卖出信号待处理

待复盘 → 观察中
待复盘 → 黑名单
```

# 13. 交易信号模块（自选生命周期修正版）

## 13.1 信号系统定位

信号系统负责根据股票所属交易系统自动识别买入信号、买点确认状态、卖出信号和风险信号。系统只提供规则化提醒和结构化记录，不自动买入或卖出。

## 13.2 交易系统决定信号规则

每套交易系统必须配置以下能力：

```text
观察策略
买入信号规则
买点确认方法
止损策略
止盈策略
卖出信号规则
```

这些规则由交易系统统一限定，用户加入自选时无需填写。

## 13.3 买入信号生成机制

观察池个股根据所属交易系统自动扫描买入信号。

状态流转：

```text
观察中 → 买入信号已生成
```

如果买入信号已生成但买点确认方法尚未满足，则继续进入：

```text
买入信号已生成 → 等待买点确认
```

该阶段只在自选-信号中展示，不进入交易页的交易中。

## 13.4 买点确认机制

系统在买入信号生成后继续判断该交易系统的买点确认方法是否满足。

当买点确认方法满足：

```text
等待买点确认 → 买入待确认
```

此时系统提醒用户确认买入。用户未确认买入前，不产生真实交易记录。

## 13.5 买入待确认

买入待确认表示系统已完成两步判断：

```text
买入信号已生成
+
买点确认方法满足
```

此时用户可以执行：

```text
确认买入
放弃本次机会
查看详情
```

## 13.6 信号等级

S/A/B/C 信号等级可继续保留，用于控制提醒强度和复盘统计。但无论信号等级多高，都不能绕过人工确认买入。

# 16. 策略回测与模拟盘模块

## 16.1 回测目标

回测用于验证策略是否具备正期望，而不是用于事后拟合。

## 16.2 回测内容

| 功能 | 说明 |
|---|---|
| 历史信号回放 | 查看过去信号出现后的走势 |
| 策略胜率统计 | 统计 1/3/5/10 日收益 |
| 盈亏比统计 | 平均盈利 / 平均亏损 |
| 最大回撤 | 评估风险 |
| 分市场环境回测 | 强势/震荡/退潮下分别统计 |
| 分板块回测 | 不同题材表现差异 |
| 分信号等级回测 | S/A/B/C 表现差异 |
| 参数优化 | 不同指标参数的效果比较 |

## 16.3 核心回测指标

```text
策略期望值 = 胜率 × 平均盈利 - 失败率 × 平均亏损
```

只有长期期望值为正、最大回撤可控、样本数量充足的策略，才允许进入正式信号池。

## 16.4 模拟盘

系统应支持模拟盘记录：

1. 模拟买入。
2. 模拟卖出。
3. 模拟仓位。
4. 模拟盈亏。
5. 策略表现。
6. 与真实交易对比。

# 17. 风控中心

## 17.1 风控规则

| 风控类型 | 规则 |
|---|---|
| 单笔止损 | 单笔亏损达到设定阈值提醒 |
| 总体回撤 | 周/月最大回撤达到阈值提醒 |
| 连续亏损 | 连续亏损 N 笔后降低信号等级 |

## 17.2 风险等级

| 等级 | 含义 | 系统处理 |
|---|---|---|
| 低 | 正常波动 | 仅记录 |
| 中 | 需要关注 | H5 提醒 |
| 高 | 需要处理 | 强提醒 |
| 极高 | 交易逻辑失效 | 建议退出或停止新交易 |

```text
查看信号快照
```

卖出提醒展示已触发止损、止盈、风险或体系卖出规则的交易中股票。

按钮：

```text
延后处理
查看详情
```

| 场景 | 要求 |
|---|---|

1. 系统交易日稳定运行。
2. 采集任务失败自动重试。
3. 数据源异常自动降级。
4. 关键任务有日志和告警。
5. H5 页面无明显卡顿。

## 24.4 兼容性

适配：

1. iOS Safari。
2. Android Chrome。
3. 微信内置浏览器。
4. 手机 QQ 浏览器。
5. 常见手机竖屏尺寸。

## 24.5 安全性

1. 用户登录鉴权。

# 25. 合规要求

## 25.1 产品合规边界

系统定位为：

```text
行情监测 + 辅助分析 + 信号提醒 + 人工确认 + 交易记录 + 复盘分析
```

系统不得在 MVP 阶段提供：

1. 自动下单。
2. 代客交易。
3. 保证收益。
4. 明确承诺稳定盈利。
5. 未授权行情数据商业化分发。
6. 诱导性买卖建议。

## 25.2 数据合规

1. 正式商业使用需优先选择授权数据接口。
2. 热榜、网页数据采集需要遵守对应平台协议。
3. 不得绕过反爬机制进行高频抓取。
4. 对外展示行情数据时需确认数据授权范围。

## 25.3 程序化交易边界

若未来接入自动下单、自动报单、自动撤单等功能，需要单独评估证券市场程序化交易相关监管要求。MVP 阶段建议不涉及自动交易。

Aquant 的核心竞争力不应只是“采集行情”和“推送指标信号”，而应是：

1. 帮助用户判断市场能不能做。

# 33. 增补目标（自选生命周期修正版）

本次增补的核心目标是：将 Aquant 的自选股管理从“简单候选池”升级为一套有明确交易系统约束的生命周期管理流程。

修正后的核心闭环为：

```text
市场发现
  ↓
确认交易系统并加入自选
  ↓
观察中
  ↓
系统生成买入信号
  ↓
系统判断买点确认方法
  ↓
提醒用户确认买入
  ↓
用户确认止损位并买入
  ↓
交易中
  ↓
系统触发卖出信号
  ↓
用户确认全部卖出
  ↓
复盘归档
```

## 33.1 本增补解决的问题

1. 股票如何从市场页加入自选。
2. 加入自选时如何确认交易系统。
3. 观察池个股如何根据所属交易系统自动生成买入信号。
4. 买入信号生成后，系统如何继续判断买点确认方法。
5. 买点满足后，如何提醒用户人工确认买入。
6. 用户确认买入时需要填写哪些字段，尤其是必须确认止损位。
7. 买入后如何进入交易页的交易中状态。
8. 交易中如何触发卖出信号并完成全部卖出。
9. 卖出后如何进入复盘流程。

# 34. 自选生命周期完整管理流程（修正版）

## 34.1 自选股定位升级

自选池不再是普通收藏夹，而是一个短线交易候选漏斗。股票从市场页热榜、涨停榜进入自选后，必须绑定明确交易系统，并在该交易系统约束下完成从观察、信号、买入、交易中、卖出到复盘的完整生命周期。

## 34.2 生命周期状态定义

| 状态 | 含义 | 所在页面 | 是否代表真实交易 |
|---|---|---|---|
| 市场候选 | 股票出现在热榜、涨停榜，尚未加入自选 | 市场 | 否 |
| 观察中 | 已加入自选，已确认交易系统 | 自选-观察 | 否 |
| 买入信号已生成 | 系统根据交易系统规则识别出买入信号 | 自选-信号 | 否 |
| 等待买点确认 | 买入信号已生成，但买点确认方法尚未满足 | 自选-信号 | 否 |
| 买入待确认 | 系统判断买点确认方法已满足，提醒用户买入 | 自选-信号 / 交易提醒入口 | 否 |
| 交易中 | 用户人工确认买入，已记录实际交易 | 交易 | 是 |
| 卖出信号待处理 | 系统触发卖出信号，等待用户确认卖出 | 交易 | 是 |
| 卖出延后处理 | 用户选择暂不处理卖出提醒 | 交易 | 是 |
| 已卖出 | 用户确认全部卖出 | 交易 / 复盘 | 已结束 |
| 待复盘 | 已卖出但尚未完成复盘 | 复盘 | 已结束 |
| 已归档 | 生命周期结束，进入历史归档 | 复盘 / 归档 | 已结束 |
| 已失效 | 观察逻辑失效，退出观察 | 自选 | 否 |
| 黑名单 | 禁止再次自动加入或推荐进入自选 | 自选 / 后台 | 否 |

## 34.3 状态流转规则

1. 市场候选点击加入自选时，必须确认交易系统。
2. 加入自选成功后进入观察中，并启用所属交易系统的观察扫描逻辑。
3. 系统根据交易系统自动生成买入信号。
4. 买入信号生成后，若买点确认方法未满足，则进入等待买点确认。
5. 买点确认方法满足后，进入买入待确认，并提醒用户确认买入。
6. 用户人工确认买入时必须确认止损位。
7. 用户确认买入后进入交易中。
8. 交易中股票按所属交易系统扫描止损、止盈和卖出信号。
9. 触发卖出信号后进入卖出信号待处理。
10. MVP 只支持全部卖出。
11. 确认全部卖出后进入待复盘。
12. 复盘后可归档、重新观察或加入黑名单。

# 36. 自选观察与信号流程（修正版）

## 36.1 自选-观察

自选-观察展示已加入自选、已确认交易系统、但尚未进入真实交易的股票。

卡片字段：股票名称、股票代码、交易系统、当前状态、入选来源、入选理由、关键观察价、距离关键价、失效条件、风险标签、下一步动作。

操作按钮：查看详情、调整观察参数、标记失效、移除自选。

## 36.2 系统自动生成买入信号

观察池个股根据所属交易系统自动扫描买入信号。每套交易系统必须配置观察策略、买入信号规则、买点确认方法、止损策略、止盈策略、卖出信号规则。

状态流转：

```text
观察中 → 买入信号已生成
```

若买点确认方法尚未满足：

```text
买入信号已生成 → 等待买点确认
```

该股票展示在自选-信号中，不进入交易中。

## 36.3 自选-信号

自选-信号展示买入信号已生成、等待买点确认、买入待确认状态的股票。

信号卡片字段：股票名称、股票代码、交易系统、当前状态、买入信号类型、信号触发时间、信号触发价格、买点确认状态、风险提示、信号失效条件。

## 36.4 买点确认方法满足

当系统判断买点确认方法满足：

```text
等待买点确认 → 买入待确认
```

此时卡片按钮变为：确认买入、放弃本次机会、查看详情。

# 37. 放弃本次机会与剔除流程（修正版）

## 37.1 放弃本次机会

以下状态均允许用户放弃本次机会：买入信号已生成、等待买点确认、买入待确认。

表单字段：

| 字段 | 类型 | 是否必填 |
|---|---|---|
| 放弃原因 | 单选 + 文本 | 是 |
| 是否继续观察 | 开关 | 是，默认继续观察 |
| 是否保留信号记录 | 开关 | 是，默认保留 |

放弃原因选项：买点不清晰、风险收益比不合适、市场转弱、板块转弱、价格偏离买点、个人不想交易。

状态流转：

```text
买入信号已生成 / 等待买点确认 / 买入待确认 → 观察中
```

如果不继续观察：

```text
买入信号已生成 / 等待买点确认 / 买入待确认 → 已失效
```

## 37.2 防重复规则

回到观察中后，本次已放弃的信号不得重复生成。系统需记录 abandoned_signal_id、abandoned_reason、abandoned_time、prevent_duplicate_signal。

## 37.3 标记失效

用户可在观察中手动标记失效，系统也可根据交易系统规则自动判断观察逻辑失效。失效后可归档或加入黑名单。

# 38. 买入确认流程（修正版）

## 38.1 买入确认定位

买入确认是用户唯一的买入决策动作。系统先自动识别买入信号并判断买点确认方法是否满足，用户只在买入待确认阶段决定是否实际买入。

## 38.2 进入条件

当系统同时满足：

```text
买入信号已生成
+
买点确认方法满足
```

状态变为：

```text
买入待确认
```

## 38.3 确认买入表单

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| 股票名称 | 只读 | 是 | 自动带入 |
| 股票代码 | 只读 | 是 | 自动带入 |
| 交易系统 | 只读 | 是 | 已确认交易系统 |
| 买入信号 | 只读 | 是 | 系统生成 |
| 买点确认结果 | 只读 | 是 | 系统判断 |
| 买入时间 | 时间 | 是 | 默认当前时间 |
| 买入价格 | 数字 | 是 | 默认当前价，可修改 |
| 买入数量 | 数字 | 是 | 用户填写 |
| 仓位比例 | 百分比 | 是 | 用户填写 |
| 止损位 | 数字 | 是 | 必须确认 |
| 目标价 | 数字 | 否 | 非必填 |
| 买入理由 | 自动生成，可编辑 | 是 | 来自信号与买点 |
| 交易计划 | 自动生成，可编辑 | 是 | 系统生成 |
| 情绪状态 | 单选 | 否 | 冷静 / 犹豫 / 冲动 / 害怕踏空 |
| 备注 | 文本 | 否 | 用户补充 |

## 38.4 强制校验

1. 必须处于买入待确认状态。
2. 必须已有确认交易系统。
3. 必须已生成买入信号。
4. 必须满足买点确认方法。
5. 必须填写买入价格、买入数量、仓位比例。
6. 必须确认止损位。
7. 目标价非必填。

未确认止损位，不允许确认买入。

## 38.5 提交后系统动作

用户确认买入后，系统创建交易记录、保存买入信号快照、保存买点确认快照、记录买入价格/数量/仓位/止损位/目标价、生成持仓记录、启动卖出信号扫描和风险监控任务。

状态流转：

```text
买入待确认 → 交易中
```

# 39. 卖出信号与卖出流程（修正版）

## 39.1 卖出优先级原则

卖出信号优先级高于买入信号和风险观察信号。交易中股票根据所属交易系统自动扫描止损策略、止盈策略、卖出信号规则。

触发后状态流转：

```text
交易中 → 卖出信号待处理
```

## 39.2 卖出提醒卡片字段

股票名称、股票代码、交易系统、卖出信号类型、触发原因、买入价、当前价、浮动盈亏、系统提示。

按钮：确认卖出、延后处理、查看详情。

## 39.3 延后处理

延后处理表单字段：延后时间、延后原因、是否继续提醒。

延后时间选项：15 分钟后、30 分钟后、收盘前、明日开盘。

状态流转：

```text
卖出信号待处理 → 卖出延后处理
卖出延后处理 → 卖出信号待处理
```

# 41. 单笔交易复盘流程

## 41.1 复盘触发条件

以下情况必须触发单笔复盘：

1. 用户全部卖出后。
2. 交易状态变为已完成。
3. 用户手动标记交易结束。
4. 持仓超过设定时间仍未处理。
5. 触发止损但用户未执行。
6. 触发止盈但用户未执行。

## 41.2 单笔复盘结构

单笔复盘分为四部分：

```text
交易前计划
  ↓
交易中执行
  ↓
交易后结果
  ↓
问题归因与改进
```

## 41.3 系统自动复盘字段

| 字段 | 说明 |
|---|---|
| buy_signal_valid | 买入是否符合系统信号 |
| buy_plan_valid | 是否符合交易计划 |
| market_state_at_buy | 买入时市场状态 |
| sector_state_at_buy | 买入时板块状态 |
| entry_quality_score | 买点质量评分 |
| exit_quality_score | 卖点质量评分 |
| max_profit_ratio | 最大浮盈 |
| max_loss_ratio | 最大浮亏 |
| final_pnl_ratio | 最终盈亏 |
| holding_days | 持仓天数 |
| risk_reward_actual | 实际盈亏比 |
| stop_loss_triggered | 是否触发止损 |
| stop_loss_executed | 是否执行止损 |
| target_triggered | 是否达到目标 |
| target_executed | 是否执行止盈 |
| plan_execution_result | 计划执行结果 |

## 41.4 用户手动复盘问题

系统应引导用户回答：

1. 买入理由是否清晰？
2. 买入是否符合系统信号？
3. 是否提前制定止损和目标位？
4. 买入后走势是否符合预期？
5. 卖出是否符合计划？
6. 是否存在冲动交易？
7. 是否存在恐惧卖出？
8. 是否存在盈利不走、亏损死扛？
9. 本次交易最大问题是什么？
10. 下次遇到类似情况应该如何处理？

## 41.5 单笔交易评分

每笔交易完成后，系统生成交易评分。

| 维度 | 权重 |
|---|---:|
| 计划完整度 | 20% |
| 买点质量 | 20% |
| 仓位控制 | 15% |
| 风控执行 | 20% |
| 卖点执行 | 15% |
| 情绪纪律 | 10% |

交易评分不只看盈利，也要看执行质量。

# 42. 每周复盘系统

## 42.1 每周复盘目标

每周复盘用于判断：

1. 本周是否适合交易。
2. 用户是否做了该做的交易。
3. 用户是否做了不该做的交易。
4. 哪些策略有效。
5. 哪些亏损来自市场，哪些来自执行。
6. 下周应该改进什么。

## 42.2 周复盘生成时间

系统每周五收盘后自动生成初版周报。用户可在周末补充主观复盘内容。

## 42.3 周复盘内容

周复盘报告包括：

1. 本周市场环境总结。
2. 本周主线板块变化。
3. 本周自选池变化。
4. 本周交易统计。
5. 本周信号表现。
6. 本周计划执行情况。
7. 本周最佳交易。
8. 本周最差交易。
9. 本周计划外交易。
10. 本周主要错误。
11. 下周交易重点。
12. 下周风险提醒。

## 42.4 周复盘核心指标

| 指标 | 说明 |
|---|---|
| total_trades | 本周交易次数 |
| win_rate | 胜率 |
| profit_loss_ratio | 盈亏比 |
| expectancy | 单笔期望值 |
| total_pnl | 总盈亏 |
| max_drawdown | 本周最大回撤 |
| avg_holding_days | 平均持仓天数 |
| plan_execution_rate | 计划执行率 |
| unplanned_trade_count | 计划外交易次数 |
| stop_loss_execution_rate | 止损执行率 |
| take_profit_execution_rate | 止盈执行率 |
| signal_trade_ratio | 信号交易占比 |
| emotion_trade_count | 情绪化交易次数 |

## 42.5 周复盘归因

| 归因类型 | 示例 |
|---|---|
| 市场问题 | 退潮期仍交易 |
| 板块问题 | 买入非主线板块 |
| 个股问题 | 选择跟风股而非核心股 |
| 买点问题 | 追高、未等待确认 |
| 卖点问题 | 止盈不及时、止损犹豫 |
| 仓位问题 | 单笔仓位过重 |
| 纪律问题 | 计划外交易 |
| 情绪问题 | 怕错过、报复性交易 |
| 策略问题 | 信号本身成功率低 |
| 数据问题 | 行情或热榜数据延迟 |

## 42.6 周复盘输出建议

系统应自动生成下周改进建议，例如：

```text
本周主要问题：计划外交易 3 次，止损执行率仅 50%。
下周建议：
1. 每日最多交易 1 笔。
2. 只交易 S/A 级信号。
3. 市场低于 50 分时禁止开新仓。
4. 所有买入必须提前设置止损。
```

# 44. 短线交易训练系统

## 44.1 训练目标

系统应帮助用户逐步形成自己的短线交易系统，而不是只依赖单次信号。

训练系统包括：

1. 盘前计划训练。
2. 盘中执行训练。
3. 盘后复盘训练。
4. 周期性总结训练。
5. 常见错误纠正训练。

## 44.2 用户错误标签库

系统应维护用户错误标签库：

| 错误标签 | 说明 |
|---|---|
| 追高买入 | 未等待回踩或确认 |
| 左侧过早买入 | 趋势未稳定提前介入 |
| 止损犹豫 | 达到止损不执行 |
| 止盈贪婪 | 达到目标不卖 |
| 卖飞恐惧 | 过早卖出强势股 |
| 报复交易 | 亏损后急于扳回 |
| 计划外交易 | 未进入计划仍买入 |
| 仓位过重 | 单笔仓位超限 |
| 频繁交易 | 交易次数过多 |
| 忽视市场 | 市场退潮仍开仓 |
| 忽视板块 | 个股脱离主线 |
| 买入跟风股 | 未买核心股 |
| 信号误判 | 技术形态理解错误 |

## 44.3 重复错误提醒

当用户连续出现同类错误时，系统应提醒：

```text
你最近 5 笔亏损交易中，有 3 笔属于“计划外交易”。
建议下周开启严格模式：只允许交易今日计划内 S/A 级信号。
```

## 44.4 严格模式

系统支持开启严格模式。

严格模式下：

1. 未确认交易系统、未进入买入待确认状态的股票不允许确认买入。
2. 市场低于设定分数时禁止新增买入待确认提醒或降低信号等级。
3. 连续亏损达到阈值后自动停止新交易提醒。
4. 单笔仓位超过上限时提醒用户调整。
5. 未确认止损位不能确认买入。
6. 未完成昨日复盘时提醒先复盘再交易。

# 48. 验收标准增补（自选生命周期修正版）

## 48.1 加入自选验收

| 验收项 | 标准 |
|---|---|
| 加入自选必须选择交易系统 | 未选择交易系统无法提交 |
| 默认选中系统推荐交易系统 | 打开表单时自动选中推荐项 |
| 用户可修改交易系统 | 可切换为其他两套体系 |
| 不要求填写修改原因 | 修改交易系统后无需填写原因 |
| 加入成功后进入观察中 | 状态正确更新 |

## 48.2 观察与信号验收

| 验收项 | 标准 |
|---|---|
| 观察股按交易系统扫描 | 不同交易系统走不同扫描规则 |
| 买入信号自动生成 | 满足规则后生成信号记录 |
| 买点未满足不进入交易中 | 仅在自选-信号展示 |
| 买点满足后进入买入待确认 | 生成用户买入提醒 |
| 放弃信号不重复生成 | 相同信号不再重复提醒 |

## 48.3 买入确认验收

| 验收项 | 标准 |
|---|---|
| 只有买入待确认才能确认买入 | 其他状态无法确认买入 |
| 确认买入必须填写止损位 | 未填写止损位无法提交 |
| 目标价非必填 | 可为空 |
| 确认买入后进入交易中 | 状态正确流转 |
| 生成交易记录 | trade_record 正确写入 |

## 48.4 交易中与卖出验收

| 验收项 | 标准 |
|---|---|
| 交易中展示买入信息 | 买入价、仓位、止损位、盈亏完整展示 |
| 触发卖出信号后提醒 | 状态进入卖出信号待处理 |
| MVP 只支持全部卖出 | 不出现部分卖出选项 |
| 确认卖出后进入待复盘 | 状态正确流转 |
| 盈亏自动计算 | 盈亏金额、比例正确 |

## 48.5 复盘入口验收

| 验收项 | 标准 |
|---|---|
| 卖出后生成复盘任务 | 复盘页出现待复盘卡片 |
| 可开始复盘 | 进入单笔复盘流程 |
| 可归档 / 重新观察 / 加黑名单 | 状态正确流转 |

# 50. 增补后的核心闭环（自选生命周期修正版）

```text
市场状态判断
  ↓
主线板块识别
  ↓
热榜 / 涨停榜发现股票
  ↓
确认交易系统并加入自选
  ↓
观察中
  ↓
系统按交易系统生成买入信号
  ↓
系统判断买点确认方法
  ↓
买入待确认
  ↓
用户确认止损位并确认买入
  ↓
交易中
  ↓
系统触发卖出信号
  ↓
用户确认全部卖出
  ↓
待复盘
  ↓
周复盘 / 月总结 / 交易系统优化
```

一句话总结：

> 交易系统决定规则，系统负责识别信号和买点，用户负责最终买入卖出确认，自选池负责完整记录生命周期。
