# Aquant 自选池管理开发计划（含提示词）

本文基于 `docs/自选池管理开发文档.md`、当前后端与 H5 代码现状制定。目标不是继续修补旧的“收藏列表式自选池”，而是把自选池重构为清晰的短线交易候选生命周期模块：

市场候选 -> 手动加入自选 -> 确认交易系统 -> 观察 -> 信号 -> 买入待确认 -> 人工买入 -> 交易中 -> 人工全部卖出 -> 待复盘 -> 归档

本计划允许清理当前自选池、信号、交易相关数据；不需要保留现有 `watch_pool`、`watch_signal`、`watch_trade` 等表中的业务数据。实现时仍需保留最新版 PRD 边界：不自动入池、不自动交易、不接券商接口、不出现诱导交易文案。

## 1. 当前现状理解

### 1.1 当前可复用能力

当前项目已经具备以下基础能力，可以保留并改造：

| 模块 | 当前文件 | 可复用点 |
|---|---|---|
| ORM 模型 | `app/models/entities.py` | 已有 `watch_pool`、`watch_pool_status_log`、`watch_signal`、`watch_signal_performance`、`watch_trade`、`watch_trade_execution` |
| H5 自选接口 | `app/api/routes/h5.py` | 已有自选、信号、交易路由，可保留路径并增强字段和状态机 |
| 自选服务 | `app/services/prd_v1.py::PrdWatchPoolService` | 已有添加、更新、剔除、黑名单、监控开关、状态日志 |
| 信号扫描 | `app/services/signal_engine.py` | 已有自选池扫描和信号保存框架 |
| 市场页加自选入口 | `frontend/src/pages/MarketPage.tsx` | 已有热门股、涨停股 “+” 入口 |
| 自选页 | `frontend/src/pages/WatchPoolPage.tsx` | 已有观察、信号、交易三块雏形 |
| 股票跳转 | `frontend/src/components/StockLink.tsx` | 已有雪球链接能力 |
| 测试入口 | `tests/test_prd_v1_api.py` | 可扩展为自选生命周期测试集 |

### 1.2 当前必须改造的问题

| 问题 | 当前表现 | 目标改造 |
|---|---|---|
| 加自选太轻 | 市场页 `+` 只弹确认框并直接提交 | 改为底部表单，必须确认交易系统、入选理由、关键观察价、失效条件 |
| 交易系统不明确 | 当前用 `operation_strategies` 数组 | 新增单值 `trading_system`，三选一：平台突破、上涨趋势、追涨接力 |
| 生命周期不完整 | 当前主要靠 `pool_status=watching/holding/completed/removed/blacklist` | 新增 `lifecycle_status`，覆盖观察、信号、买入待确认、交易中、卖出待处理、待复盘、归档、失效、黑名单 |
| 信号状态不足 | 当前 `signal_status=pending/ignored/confirmed_buy` 等 | 增加 `signal_generated/waiting_buy_point/buy_pending_confirm/abandoned/confirmed_buy/invalid` |
| 买入确认约束不足 | 当前未强制买点确认和止损价 | 后端强制 `buy_pending_confirm + buy_point_confirmed + stop_loss_price` |
| 卖出流程过宽 | 当前支持部分卖出 | MVP 阶段只支持全部卖出，去掉部分卖出入口和状态 |
| 交易页数据不真实 | 当前自选页交易区部分逻辑仍基于 `watch_pool` 状态 | 交易区必须读取 `watch_trade` 和 `watch_trade_execution` |
| 状态日志不够完整 | 当前日志仅记录 from/to/reason | 增加 `operation_type` 和 `snapshot`，所有关键动作写日志 |
| 旧字段语义混杂 | `reason/source_reason/remark/labels` 混用 | 梳理为 `entry_reason/risk_tags/user_remark` 等清晰字段 |

## 2. 清理原则

### 2.1 数据清理

本次不保留当前自选池及交易数据。开发前允许清空以下表：

| 表名 | 处理方式 | 原因 |
|---|---|---|
| `watch_pool` | 清空或重建 | 字段语义需要升级，旧数据没有保留价值 |
| `watch_pool_status_log` | 清空或重建 | 生命周期日志结构需要新增 snapshot |
| `watch_signal` | 清空或重建 | 信号状态机变化较大 |
| `watch_signal_performance` | 清空或重建 | 依赖旧信号 |
| `watch_trade` | 清空或重建 | 交易状态与字段需要升级 |
| `watch_trade_execution` | 清空或重建 | 执行流水依赖旧交易 |
| `review_trade` | 清空或保留表结构 | 单笔复盘依赖交易完成后重新生成 |

建议采用开发环境硬重建方式：新增一个干净迁移，将上述表调整到目标结构；如果远程库中已有这些表，可先备份表结构，再 `TRUNCATE` 业务数据。

### 2.2 代码清理

需要清理或停用的旧逻辑：

| 旧逻辑 | 位置 | 处理 |
|---|---|---|
| `operation_strategies` 作为核心交易系统 | `WatchPool`、H5 表单 | 停用为兼容字段，新流程使用 `trading_system` |
| `buy_point_types` 多选作为核心入口 | `WatchPool`、H5 表单 | 降级为策略配置参考，新增自选时不作为必填 |
| `partial_sold` 部分卖出 | `WatchTrade`、`confirm_sell`、前端交易区 | MVP 删除前端入口，后端拒绝部分卖出 |
| 自选页交易区基于 `watch_pool holdingItems` | `WatchPoolPage.tsx` | 改为读取 `watch_trade` |
| 市场页简单确认添加 | `MarketPage.tsx` | 替换为加自选底部弹层 |
| 中文乱码状态兼容判断 | `WatchPoolPage.tsx`、`signal_engine.py` | 全部改为英文枚举状态，中文仅前端映射展示 |
| 非文档涉及的旧自选字段展示 | 前端卡片 | 删除或隐藏，只展示文档要求字段 |

## 3. 目标数据结构

### 3.1 `watch_pool`

建议最终字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | Integer | 是 | 主键 |
| `stock_code` | String(16) | 是 | 标准股票代码 |
| `stock_name` | String(64) | 是 | 股票名称 |
| `sector_name` | String(64) | 否 | 所属板块 |
| `entry_source` | String(32) | 是 | `hot_stock` / `limit_up` / `manual` |
| `entry_reason` | Text | 是 | 入选理由 |
| `source_platform` | String(32) | 否 | 来源平台 |
| `source_rank` | Integer | 否 | 来源排名 |
| `source_score` | Float | 否 | 平台原始分数 |
| `source_reason` | Text | 否 | 平台原始原因 |
| `system_recommendation` | String(32) | 否 | 系统推荐交易系统 |
| `trading_system` | String(32) | 是 | `platform_breakout` / `uptrend` / `relay` |
| `lifecycle_status` | String(32) | 是 | 生命周期状态 |
| `key_observe_price` | Float | 是 | 关键观察价 |
| `invalid_condition` | Text | 是 | 失效条件 |
| `risk_tags` | JSON | 否 | 风险标签 |
| `signal_enabled` | Boolean | 是 | 是否启用买点监控 |
| `latest_signal_id` | Integer | 否 | 最新信号 |
| `xueqiu_url` | String(512) | 否 | 雪球链接 |
| `user_remark` | Text | 否 | 用户备注 |
| `is_blacklist` | Boolean | 是 | 是否黑名单 |
| `blacklist_reason` | Text | 否 | 黑名单原因 |
| `active` | Boolean | 是 | 是否有效 |
| `added_trade_date` | Date | 否 | 加入日期 |
| `removed_at` | DateTime | 否 | 剔除时间 |
| `archive_reason` | Text | 否 | 归档原因 |
| `created_at` / `updated_at` | DateTime | 是 | 时间戳 |

兼容字段处理建议：

- `pool_status` 暂时保留，但只作为兼容字段，和 `lifecycle_status` 双写。
- `reason` 可保留但不再作为主字段，写入时同步 `entry_reason`。
- `labels` 可保留为用户标签，但风险标签使用 `risk_tags`。
- `operation_strategies`、`buy_point_types` 不再作为主流程必需字段。

### 3.2 `watch_pool_status_log`

新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `operation_type` | String(32) | `add_watch` / `adjust_observe_params` / `mark_invalid` / `confirm_buy` / `confirm_sell` / `archive` 等 |
| `snapshot` | JSON | 状态变化时的关键字段快照 |

### 3.3 `watch_signal`

新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `trading_system` | String(32) | 所属交易系统 |
| `buy_point_confirmed` | Boolean | 买点确认方法是否满足 |
| `buy_point_confirm_time` | DateTime | 买点确认时间 |
| `buy_point_confirm_price` | Float | 买点确认价格 |
| `abandoned_flag` | Boolean | 是否放弃本次机会 |
| `abandoned_reason` | Text | 放弃原因 |
| `abandoned_time` | DateTime | 放弃时间 |
| `prevent_duplicate_signal` | Boolean | 是否阻止相同信号重复生成 |
| `trigger_signature` | String(128) | 去重签名 |

### 3.4 `watch_trade`

新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `trading_system` | String(32) | 交易系统 |
| `buy_reason` | Text | 买入理由 |
| `trade_plan` | Text | 交易计划 |
| `emotion_state` | String(32) | 买入时情绪状态 |

MVP 约束：

- `trade_status` 不再进入 `partial_sold`。
- 只支持 `open/completed/cancelled/invalid` 等清晰状态。

### Phase 3：自选服务重构

目标：把 `PrdWatchPoolService` 从“简单收藏”改造成“生命周期管理服务”。

改动文件：

- `app/services/prd_v1.py`

任务：

1. 重写 `ACTIVE_STATUSES`：
   - `watching`
   - `signal_generated`
   - `waiting_buy_point`
   - `buy_pending_confirm`
   - `trading`
   - `sell_signal_pending`
   - `sell_delayed`
2. `add_watch` 必须校验：
   - `stock_code`
   - `trading_system`
   - `entry_reason`
   - `key_observe_price > 0`

5. 新增 `transition` 统一状态流转。
6. 新增 `validate_transition` 防止非法跳转。
7. 新增 `mark_invalid`。
8. 新增 `recommend_trading_system`。
9. 所有关键动作写 `watch_pool_status_log`，包括 `operation_type` 和 `snapshot`。

### Phase 5：信号引擎改造

目标：信号只从手动自选、开启监控、绑定交易系统的股票中生成。

改动文件：

- `app/services/signal_engine.py`
- `app/strategies/*`

任务：

1. 扫描对象必须满足：
   - `lifecycle_status=watching`
   - `signal_enabled=true`
   - 非黑名单
   - 已设置 `trading_system`
2. 按交易系统选择策略：
   - `platform_breakout` -> 平台突破确认
   - `uptrend` -> B15 底背离、支撑买点
   - `relay` -> 接力/涨停后观察策略，MVP 可先预留
3. 保存信号时写入：
   - `trading_system`
   - `buy_point_confirmed`
   - `trigger_signature`
4. 根据买点确认状态设置：
   - `waiting_buy_point`
   - `buy_pending_confirm`
5. 放弃机会后，相同 `trigger_signature` 不重复生成。
6. 信号生成后更新 `watch_pool.lifecycle_status` 和 `latest_signal_id`。

验收：

- 非自选股票不会生成买入信号。
- 未开启监控不会生成买入信号。
- 放弃机会后不会重复生成同类信号。

### Phase 6：交易确认改造

目标：买入、卖出都必须人工确认；买入前必须止损；卖出 MVP 只支持全部卖出。

改动文件：

- `app/api/routes/h5.py`
- 后续可抽出 `app/services/trade_service.py`

任务：

1. `confirm_buy`：
   - 阻止重复确认同一信号。
   - 校验 `buy_pending_confirm`。
   - 校验 `buy_point_confirmed`。
   - 校验 `stop_loss_price`。
   - 创建或更新 `watch_trade`。
   - 写入 `watch_trade_execution`，`execution_type=buy`。
   - 更新 `watch_signal` 为 `confirmed_buy`。
   - 更新 `watch_pool.lifecycle_status=trading`，关闭买点监控。
2. `confirm_sell`：
   - 只接受 `is_full_exit=true`。
   - 自动按 `remaining_amount` 全部卖出。
   - 写入 `watch_trade_execution`，`execution_type=sell`。
   - 更新 `watch_trade.trade_status=completed`。
   - 更新 `watch_pool.lifecycle_status=pending_review`。
   - 生成 `review_trade`。

验收：

- 未填止损无法确认买入。
- 部分卖出被拒绝。
- 全部卖出后出现待复盘记录。

## 9. 风险点

| 风险 | 影响 | 处理建议 |
|---|---|---|
| 当前文件存在中文乱码 | 前端展示和测试可读性差 | 开发时顺手修复相关文件编码和中文文案 |
| 底部导航口径仍可能冲突 | 主 PRD 是“市场/自选/复盘/我的”，自选文档强调交易入口 | 本轮不改底部导航，交易仍作为自选页 Tab |
| 清空 watch 数据可能影响演示 | H5 暂时空数据 | 清空后初始化少量符合新流程的 mock 数据 |
| 信号策略细节不足 | relay 等策略可能无法完整落地 | MVP 先实现字段和状态机，复杂策略预留 |
| 一次性删除字段风险高 | 迁移失败或旧接口报错 | 第一轮保留旧字段但主流程不再使用；稳定后再删字段 |
