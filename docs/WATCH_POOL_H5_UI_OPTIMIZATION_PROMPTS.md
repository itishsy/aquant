# 自选 H5 观察-信号-交易详情页优化开发明细

## 背景

当前 H5 自选页已经承载观察股、信号、交易三条业务流，但页面交互和详情展示逐步演进后出现了不一致：

- 观察列表中点击股票名称和点击卡片，会进入两套不同详情页。
- 股票名称弹出的详情页有 K 线 Tab，但观察卡片详情页没有统一复用。
- 列表中直接出现“雪球”按钮，挤占信息区域，也让列表操作重心不清晰。
- 观察、信号、交易详情样式不一致，字段展示有重复、空值、与当前决策无关的问题。
- 抽屉在小屏或窄屏浏览器中左右安全间距不足。

本优化只处理 H5 自选页前端交互和展示，不改后端业务流程，不影响市场页、admin、任务、规则扫描等其它模块。

## 优化目标

1. 统一自选页详情入口。
2. 观察、信号、交易使用一致的详情抽屉骨架。
3. 详情字段按业务场景分别展示，避免重复字段和无意义字段。
4. 详情抽屉内统一提供 K 线 Tab。
5. 列表只展示摘要，不再显示雪球按钮。
6. 雪球入口移动到详情抽屉右上角图标按钮。
7. 优化抽屉左右安全边距，适配较窄手机屏幕。
8. 保持现有确认买入、放弃信号、确认卖出、编辑观察、规则试算等业务接口不变。

## 功能边界

本次要做：

- 改 `frontend/src/pages/WatchPoolPage.tsx`。
- 必要时小幅调整 `frontend/src/components/StockLink.tsx`，让自选页可接管股票详情入口。
- 必要时调整 `frontend/src/styles/app.css` 的通用安全边距。
- 复用已有 `KlineChart` 和现有 H5 API。

本次不做：

- 不改数据库结构。
- 不改后端接口语义。
- 不改规则扫描、交易确认、邮件通知逻辑。
- 不重构市场页股票详情弹窗。
- 不新增复杂路由页面。

## 现有流程理解

### 观察

观察股来自 `watch_pool`。用户关注的是：

- 为什么加入观察。
- 当前交易体系和阶段是什么。
- 核心参数是否合理。
- 观察是否仍有效。
- 当前规则是否满足。
- 下一步应该等什么或处理什么。

主要操作：

- 查看详情。
- 查看 K 线。
- 编辑观察参数。
- 规则试算。
- 开启/关闭监控。
- 标记失效。
- 剔除。
- 加入黑名单。

### 信号

信号来自 `watch_signal`。用户关注的是：

- 什么规则触发了信号。
- 触发价格和时间。
- 触发原因是否可信。
- 数据是否新鲜。
- 邮件是否发送。
- 是否需要确认买入、放弃或人工处理风险。

主要操作：

- 买点信号：确认买入、放弃本次机会。
- 风险/失效/卖点/止损信号：查看原因和人工处理。
- 查看 K 线辅助判断。

### 交易

交易来自 `watch_trade`。用户关注的是：

- 当前持仓盈亏。
- 止损和目标。
- 当前交易阶段。
- 进入交易的规则。
- 当前监控哪些卖点/止损规则。
- 是否有待处理卖点/止损信号。
- 执行流水。

主要操作：

- 查看交易详情。
- 查看 K 线。
- 查看执行流水。
- 确认全部卖出。

## 统一交互设计

### 列表点击

- 观察列表：点击卡片或股票名称，都打开观察详情抽屉。
- 信号列表：点击卡片或股票名称，都打开信号详情抽屉。
- 交易列表：点击卡片或股票名称，都打开交易详情抽屉。
- 列表不再出现雪球按钮。
- 列表保留主要摘要和主操作，不承载完整详情。

### 统一详情抽屉骨架

三类详情共享同一抽屉结构：

```text
顶部：
  股票名称 股票代码
  最新价 涨跌幅
  右上角：雪球图标按钮

标签区：
  交易体系 / 当前状态 / 阶段或信号类型

Tab：
  详情 / 日K线

内容区：
  按观察、信号、交易分别展示字段

底部操作区：
  根据类型展示对应操作
```

### 抽屉样式要求

- `Popup` 底部抽屉。
- 顶部圆角保持当前风格。
- 左右 padding 使用安全边距：

```css
padding-left: max(14px, env(safe-area-inset-left));
padding-right: max(14px, env(safe-area-inset-right));
```

- 内容卡片不贴边。
- 按钮在窄屏下不挤压文字，必要时两列展示。
- 不使用过重视觉装饰，保持当前 H5 风格。

## 字段展示设计

### 统一头部字段

三类详情顶部统一展示：

- 股票名称。
- 股票代码。
- 最新价。
- 涨跌幅。
- 右上角雪球图标按钮。

这些字段在详情内容区不再重复展示。

### 观察详情重点字段

突出字段：

- 当前状态。
- 交易体系。
- 当前阶段。
- 下一步动作。
- 核心观察参数：
  - 箱体上沿。
  - 平台支撑位。
  - 关键观察价。
  - 自动剔除价。
- 失效条件。
- 入选理由。
- 风险标签。
- 规则试算结果。

次要字段：

- 入选时间。
- 入选来源。
- 板块。
- 用户备注。
- 参数详情。

不展示或弱化：

- 最新价、涨幅，头部已有。
- 股票代码，头部已有。
- 空字段。
- 重复交易体系字段。

### 信号详情重点字段

突出字段：

- 信号类型：买点、卖点、风险、止损。
- 信号状态。
- 触发规则中文名。
- 规则周期。
- 触发价。
- 触发时间。
- 触发原因。
- 数据新鲜度摘要：
  - data_status。
  - latest_kline_time。
  - expected_latest_time。
  - quote_update_time。
- 风险说明。
- 邮件提醒状态。

买点信号额外突出：

- 确认买入。
- 放弃本次机会。

风险/失效信号额外突出：

- 风险类型。
- 人工处理提示。

不展示或弱化：

- 最新价、涨幅，头部已有。
- 交易体系字段重复展示，放到标签区即可。
- 没有值的止损价、目标价。
- 原始 `snapshot_json` 大段 JSON。

### 交易详情重点字段

突出字段：

- 交易状态。
- 当前阶段。
- 买入均价。
- 剩余数量。
- 仓位。
- 浮动盈亏金额和比例。
- 止损价。
- 目标价。
- 下一步动作。
- 进入交易的规则。
- 当前监控卖点规则。
- 当前监控止损规则。
- 最新待处理卖点/止损信号。
- 执行流水入口。

次要字段：

- 首次买入时间。
- 买入理由。
- 交易计划。
- 情绪状态。
- 关联观察参数。

不展示或弱化：

- 交易体系重复字段，标签区已有即可。
- 与当前持仓决策无关的观察字段。
- 空规则列表。

## 组件整改建议

### 新增或抽取组件

建议在 `WatchPoolPage.tsx` 内先局部抽取，避免过早跨文件重构：

- `UnifiedStockDetailDrawer`
- `DetailHeader`
- `DetailTabs`
- `DetailFieldGrid`
- `DetailActions`

如果单文件过大，再拆到：

```text
frontend/src/components/watch/UnifiedStockDetailDrawer.tsx
```

### 详情状态设计

建议使用一个统一状态：

```ts
type DetailKind = "watch" | "signal" | "trade";

const [detailTarget, setDetailTarget] = useState<{
  kind: DetailKind;
  item: any;
} | null>(null);

const [detailTab, setDetailTab] = useState<"detail" | "kline">("detail");
```

打开详情：

```ts
function openDetail(kind: DetailKind, item: any) {
  setDetailTarget({ kind, item });
  setDetailTab("detail");
  setRulePreview(null);
}
```

### StockLink 处理

`StockLink` 当前自带详情弹窗。自选页应该接管点击行为：

- 给 `StockLink` 增加可选 `onOpenDetail`。
- 自选页传入 `onOpenDetail={() => openDetail(kind, item)}`。
- 如果没有传 `onOpenDetail`，其它页面仍使用原 `StockLink` 弹窗能力。

这样不影响市场页和其它模块。

- 详情抽屉有 `详情 / 日K线` Tab。
- 三类详情字段无明显重复、空值堆砌。
- 小屏左右有安全间距。
- 现有业务操作不失效。

## 风险点

- 当前 `WatchPoolPage.tsx` 已经较大，继续堆逻辑会增加维护成本；如改动超过预期，应拆分详情抽屉组件。
- `StockLink` 被多页面使用，新增外部接管能力时必须保持默认行为不变。
- K 线图在 Popup 中渲染可能需要 resize；如果图表空白，应检查 `KlineChart` 初始化和容器尺寸。
- 后端字段存在缺失或旧数据为空时，前端必须容错，不应因为规则名、体系名、snapshot 缺失而报错。
