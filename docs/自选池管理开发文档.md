# Aquant 自选池管理开发文档

本文档基于 `docs/Aquant PRD_v1.0_自选池管理.md`，结合当前 Aquant 后端、H5 前端、数据库模型与测试现状整理。目标是把“自选池”从简单收藏/列表，升级为“市场候选 -> 确认交易系统 -> 观察 -> 信号 -> 买入待确认 -> 人工买入 -> 交易中 -> 卖出 -> 复盘”的完整生命周期管理模块。

## 1. PRD 核心理解

### 1.1 模块定位

自选池不是普通收藏夹，而是短线交易候选漏斗。股票从市场页热榜、涨停榜进入自选后，必须绑定明确交易系统，并由该交易系统决定后续观察策略、买入信号规则、买点确认方法、止损策略、止盈策略、卖出信号规则。

系统只负责识别、提醒、记录和复盘，所有买入、卖出必须由用户人工确认，不能自动下单、自动报单、自动撤单，也不能出现诱导交易文案。

### 1.2 三套交易系统

加入自选时必须确认一套交易系统，默认可由系统推荐，用户可修改，不需要填写修改原因。

可选交易系统：

- 平台突破
- 上涨趋势
- 追涨接力

加入自选时不要求用户填写这些系统的内部规则，规则由交易系统配置统一限定。

### 1.3 生命周期状态

PRD 定义的核心状态如下：

| 状态 | 含义 | 所属页面 | 是否真实交易 |
|---|---|---|---|
| 市场候选 | 出现在热榜、涨停榜，尚未加入自选 | 市场 | 否 |
| 观察中 | 已加入自选，已确认交易系统 | 自选-观察 | 否 |
| 买入信号已生成 | 系统识别出买入信号 | 自选-信号 | 否 |
| 等待买点确认 | 信号已生成，但买点确认方法未满足 | 自选-信号 | 否 |
| 买入待确认 | 买点确认满足，等待用户确认买入 | 自选-信号 / 交易提醒入口 | 否 |
| 交易中 | 用户人工确认买入，形成真实交易记录 | 交易 | 是 |
| 卖出信号待处理 | 系统触发卖出信号，等待用户处理 | 交易 | 是 |
| 卖出延后处理 | 用户选择暂不处理卖出提醒 | 交易 | 是 |
| 已卖出 | 用户确认全部卖出 | 交易 / 复盘 | 已结束 |
| 待复盘 | 已卖出但未完成复盘 | 复盘 | 已结束 |
| 已归档 | 生命周期结束，进入历史归档 | 复盘 / 归档 | 已结束 |
| 已失效 | 观察逻辑失效，退出观察 | 自选 | 否 |
| 黑名单 | 禁止再次进入观察 | 自选 / 后台 | 否 |

### 1.4 关键约束

- 加入自选必须确认交易系统。
- 买入确认必须填写止损位，未确认止损位不能完成买入。
- 只有人工确认买入后，才进入交易页“交易中”。
- 放弃本次机会后，相同信号不得重复生成。
- MVP 阶段只支持全部卖出，不支持部分卖出。
- 信号、买入、卖出、复盘相关文案必须体现“仅作为交易辅助，请结合个人交易规则确认”。

### 2.3 已实现能力

- 市场页可通过“+”手动添加自选，后端 `POST /api/h5/watch-pool` 写入 `watch_pool`。
- 重复添加有效自选时会更新已有记录，不重复创建。
- 添加、删除、黑名单、恢复会写入 `watch_pool_status_log`。
- 信号表 `watch_signal` 已关联 `watch_id`。

- H5 自选页已展示观察、信号、交易三个区块。

### 2.4 当前主要差距

| PRD 要求 | 当前现状 | 差距 |
|---|---|---|
| 加入自选必须确认交易系统 | 当前用 `operation_strategies` 数组，未强制单选交易系统 | 需新增/明确 `trading_system` |
| 系统推荐交易系统 | 当前没有推荐字段 | 需新增 `system_recommendation` |
| 关键观察价必填 | 当前仅有 `entry_price`，语义不完整 | 需新增 `key_observe_price` |
| 失效条件必填 | 当前 `watch_pool` 无 `invalid_condition` | 需新增字段 |
| 风险标签 | 当前 `labels` 可复用但语义混合 | 建议新增 `risk_tags` |
| 生命周期状态 | 当前 `pool_status` 状态较粗：watching/holding/completed/removed/blacklist | 需统一状态字典 |
| 买点确认状态 | 当前 `watch_signal` 无 `buy_point_confirmed` 等字段 | 需补字段 |
| 放弃本次机会 | 当前 ignore/false positive 不等于“放弃机会” | 需新增 abandoned 相关能力 |
| 放弃后防重复 | 当前只有同日去重，不支持 abandoned 防重复 | 需补唯一规则/扫描过滤 |
| 买入确认强制止损 | 当前 confirm-buy 没有强制校验 stop_loss_price | 需补后端校验和前端必填 |
| MVP 只支持全部卖出 | 当前支持部分卖出 | 需按 PRD 限制 H5 与后端 |
| 独立交易导航 | 当前底部为市场/自选/复盘/我的，交易在自选页 Tab | 与该 PRD 有冲突，需产品口径确认 |

## 3. 产品口径对齐建议

当前仓库主 PRD 曾要求 H5 底部导航为“市场 / 自选 / 复盘 / 我的”，而本自选池 PRD 写的是“市场 / 自选 / 交易 / 复盘”。这是一个显式冲突。

建议处理方式：

- 若以自选池 PRD 为准：新增 `/trades` 一级 H5 页面，并把交易中、买入待确认、卖出提醒迁移到交易页。
- 若以当前主系统 PRD 为准：保留底部“市场 / 自选 / 复盘 / 我的”，但在自选页内部保留“观察 / 信号 / 交易”三段。

在未进一步确认前，建议第一阶段先不改底部导航，只把生命周期、字段、接口和表单规则补齐；交易页独立化放到第二阶段。

## 4. 目标数据模型

### 4.1 watch_pool 增量字段

建议通过迁移为 `watch_pool` 增加以下字段，全部 nullable 或带默认值，避免破坏已有数据：

| 字段 | 类型 | 说明 |
|---|---|---|
| `entry_source` | String(32) | 入选来源：hot_stock / limit_up / manual |
| `entry_reason` | Text | 入选理由，可由来源原因带入 |
| `trading_system` | String(32) | 用户确认交易系统：platform_breakout / uptrend / relay |
| `system_recommendation` | String(32) | 系统推荐交易系统 |
| `lifecycle_status` | String(32) | 生命周期状态，建议逐步替代 `pool_status` |
| `key_observe_price` | Float | 关键观察价 |
| `invalid_condition` | Text | 观察失效条件 |
| `risk_tags` | JSON | 风险标签 |
| `signal_enabled` | Boolean | 是否启用信号扫描，兼容 `monitor_enabled` |
| `latest_signal_id` | Integer | 最新信号 ID |
| `user_remark` | Text | 用户备注，兼容 `remark` |

兼容策略：

- 初期 `pool_status` 和 `lifecycle_status` 双写。
- 初期 `operation_strategies[0]` 可映射到 `trading_system`。
- 初期 `monitor_enabled` 和 `signal_enabled` 双写。
- 等前后端稳定后，再逐步减少旧字段展示。

### 4.2 watch_signal 增量字段

建议新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `trading_system` | String(32) | 所属交易系统 |
| `buy_point_confirmed` | Boolean | 买点确认方法是否满足 |
| `buy_point_confirm_time` | DateTime | 买点确认时间 |
| `buy_point_confirm_price` | Float | 买点确认价格 |
| `abandoned_flag` | Boolean | 是否放弃本次机会 |
| `abandoned_reason` | Text | 放弃原因 |
| `abandoned_time` | DateTime | 放弃时间 |
| `prevent_duplicate_signal` | Boolean | 是否阻止相同信号重复生成 |

状态建议：

| 业务状态 | 建议存储值 |
|---|---|
| 买入信号已生成 | `signal_generated` |
| 等待买点确认 | `waiting_buy_point` |
| 买入待确认 | `buy_pending_confirm` |
| 已放弃 | `abandoned` |
| 已确认买入 | `confirmed_buy` |
| 已失效 | `invalid` |

### 4.3 watch_trade / watch_trade_execution 调整

当前交易表可复用，但需补充或明确以下字段语义：

- `trading_system`：建议新增到 `watch_trade`。
- `buy_reason`：可使用 `remark` 或新增字段。
- `trade_plan`：建议新增 Text。
- `emotion_state`：建议新增 String。
- `sell_reason`：当前在 `watch_trade_execution.execution_reason`，可复用。

MVP 阶段需要禁止部分卖出：

- H5 卖出表单只显示“确认全部卖出”。
- 后端 `confirm_sell` 若 `amount < remaining_amount` 且未明确允许部分卖出，应返回错误。
- `watch_trade.trade_status` 不再进入 `partial_sold`，除非未来产品重新打开部分卖出。

### 4.4 watch_pool_status_log 扩展建议

当前日志表可用。建议补充：

| 字段 | 类型 | 说明 |
|---|---|---|
| `snapshot` | JSON | 状态变化时快照 |
| `operation_type` | String(32) | add/update/invalid/remove/blacklist/confirm_buy/sell/review |

如果不想扩表，也可以将快照写入新增操作日志表或复用 `config_operation_log`。

## 5. 后端 API 设计

### 5.1 自选池 API

保留现有路径并增强字段：

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/h5/watch-pool` | 自选列表，支持状态、交易系统筛选 |
| `GET` | `/api/h5/watch-pool/summary` | 汇总数量 |
| `GET` | `/api/h5/watch-pool/{watch_id}` | 自选详情 |
| `POST` | `/api/h5/watch-pool` | 确认交易系统并加入自选 |
| `PUT` | `/api/h5/watch-pool/{watch_id}` | 编辑观察参数 |
| `DELETE` | `/api/h5/watch-pool/{watch_id}` | 移除自选 |
| `POST` | `/api/h5/watch-pool/{watch_id}/invalid` | 标记失效 |
| `POST` | `/api/h5/watch-pool/{watch_id}/blacklist` | 加入黑名单 |
| `POST` | `/api/h5/watch-pool/{watch_id}/restore` | 恢复观察 |
| `GET` | `/api/h5/watch-pool/{watch_id}/status-logs` | 生命周期日志 |

`POST /api/h5/watch-pool` 必填字段：

```json
{
  "stock_code": "603019.SH",
  "stock_name": "中科曙光",
  "entry_source": "hot_stock",
  "sector_name": "算力",
  "system_recommendation": "uptrend",
  "trading_system": "uptrend",
  "entry_reason": "热榜关注度较高",
  "key_observe_price": 50.8,
  "invalid_condition": "跌破 MA20 或放量破位",
  "risk_tags": ["高位", "板块分化"],
  "user_remark": ""
}
```

后端校验：

- `stock_code` 必须合法。
- `trading_system` 必填且只能是三套系统之一。
- `entry_reason` 必填。
- `key_observe_price` 必填且大于 0。
- `invalid_condition` 必填。
- 黑名单股票重新加入需前端二次确认，并在 payload 带 `confirm_blacklist_risk=true`。
- 有效状态中重复添加同股时，更新现有记录而不是新建。

### 5.2 信号 API

增强现有信号接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/h5/watch-signals` | 信号列表 |
| `GET` | `/api/h5/watch-signals/recent` | 最近信号 |
| `POST` | `/api/h5/watch-signals/{signal_id}/abandon` | 放弃本次机会 |
| `POST` | `/api/h5/watch-signals/{signal_id}/confirm-buy` | 人工确认买入 |
| `POST` | `/api/h5/watch-signals/{signal_id}/invalidate` | 信号失效 |

放弃机会 payload：

```json
{
  "abandoned_reason": "价格偏离买点",
  "continue_watch": true,
  "keep_signal_record": true,
  "prevent_duplicate_signal": true
}
```

放弃后状态流转：

- `continue_watch=true`：`watch_pool.lifecycle_status = watching`
- `continue_watch=false`：`watch_pool.lifecycle_status = invalid`
- `watch_signal.signal_status = abandoned`
- 后续扫描时跳过相同 `watch_id + trading_system + buy_point_type + signal_type + trigger_signature`

### 5.3 买入确认 API

现有接口：`POST /api/h5/watch-signals/{signal_id}/confirm-buy`

必须补充校验：

- 信号状态必须是 `buy_pending_confirm`。
- `buy_point_confirmed=true`。
- 必须存在 `trading_system`。
- `buy_price` 必填。
- `amount` 必填。
- `position_ratio` 必填。
- `stop_loss_price` 必填。
- 同一信号只能确认一次。

建议 payload：

```json
{
  "buy_time": "2026-05-14T10:30:00",
  "buy_price": 50.2,
  "amount": 100,
  "position_ratio": 0.1,
  "stop_loss_price": 48.5,
  "target_price": 55,
  "buy_reason": "买点确认满足",
  "trade_plan": "跌破止损位退出，冲高量价背离观察卖出",
  "emotion_state": "calm",
  "remark": ""
}
```

确认成功后：

- 创建或更新 `watch_trade`。
- 写入 `watch_trade_execution`，`execution_type=buy`。
- `watch_signal.signal_status=confirmed_buy`。
- `watch_pool.lifecycle_status=trading`。
- `watch_pool.monitor_enabled=false`，但卖出/风险扫描不受影响。
- 写入状态日志。

### 5.4 卖出 API

现有接口：`POST /api/h5/watch-trades/{trade_id}/confirm-sell`

MVP 要求只支持全部卖出：

- H5 不展示部分卖出。
- 后端校验 `amount == remaining_amount` 或 payload 带 `is_full_exit=true` 后自动使用剩余数量。
- 确认卖出后 `watch_trade.trade_status=completed`。
- `watch_pool.lifecycle_status=sold` 或 `pending_review`。
- 生成 `review_trade` 待复盘。

## 6. 前端改造方案

当前 `MarketPage.tsx` 点击 `+` 后仅弹确认框并直接提交。需改为底部弹层表单。

表单字段：

| 字段 | 类型 | 默认值 |

| 股票名称 | 只读 | 市场卡片带入 |
| 股票代码 | 只读 | 市场卡片带入 |
| 入选来源 | 只读 | 热榜 / 涨停榜 |
| 所属板块 | 只读 | 市场卡片带入 |
| 系统推荐交易系统 | 只读 | 根据来源和板块规则生成 |

## 7. 信号扫描设计

当前 `SignalEngine` 已有基础扫描，但状态和字段需要按本 PRD 对齐。

### 7.1 扫描对象

只扫描满足以下条件的自选：

- `lifecycle_status=watching` 或兼容 `pool_status=watching`
- `signal_enabled=true` 或兼容 `monitor_enabled=true`
- `is_blacklist=false`
- 已确认 `trading_system`

### 7.2 策略选择

根据 `trading_system` 决定策略集合：

| 交易系统 | 买入信号方向 |
|---|---|
| 平台突破 | 平台突破确认买点 |
| 上涨趋势 | MA20 / 趋势低吸 / B15 底背离 |
| 追涨接力 | 人气涨停、MA5 支撑、接力确认 |

三套系统详细规则不在本 PRD 展开，开发时先保留策略注册框架，并将当前已有策略映射到对应交易系统。

### 7.3 买点确认

信号生成后不一定立即进入买入待确认：

- 初始：`signal_status=signal_generated`
- 买点未满足：`signal_status=waiting_buy_point`
- 买点满足：`signal_status=buy_pending_confirm`

前端只有 `buy_pending_confirm` 才显示“确认买入”。

### 7.4 防重复

需要在扫描时排除：

- 已有同一 `stock_code + trading_system + buy_point_type + signal_type + trigger_date` 信号。
- 已被用户放弃且 `prevent_duplicate_signal=true` 的同类信号。
- 已确认买入且交易未完成的股票，不再生成买入信号。

## 8. 状态流转设计

建议统一状态枚举：

| 中文 | 存储值 |
|---|---|
| 观察中 | `watching` |
| 买入信号已生成 | `signal_generated` |
| 等待买点确认 | `waiting_buy_point` |
| 买入待确认 | `buy_pending_confirm` |
| 交易中 | `trading` |
| 卖出信号待处理 | `sell_signal_pending` |
| 卖出延后处理 | `sell_delayed` |
| 已卖出 | `sold` |
| 待复盘 | `pending_review` |
| 已归档 | `archived` |
| 已失效 | `invalid` |
| 黑名单 | `blacklist` |
| 已移除 | `removed` |

兼容现有状态：

| 现有值 | 新值 |
|---|---|
| `watching` | `watching` |
| `triggered` | `signal_generated` |
| `holding` / `open` | `trading` |
| `completed` | `sold` 或 `pending_review` |
| `removed` | `removed` |
| `blacklist` | `blacklist` |

## 11. 风险与注意事项

- 这份自选池 PRD 与当前全局 PRD 的底部导航口径存在冲突，需要在实现独立交易页前确认。
- 当前 `watch_pool.operation_strategies` 和 `buy_point_types` 是数组，PRD 更偏向一个明确交易系统；建议保留旧字段但新增 `trading_system`。
- 当前确认卖出支持部分卖出，与 PRD MVP 只支持全部卖出冲突，需要在后端和前端同时收敛。
- 当前 `SignalEngine` 中部分中文状态存在编码显示异常，需要在实施时统一状态枚举，不再依赖中文状态做查询。
- 文案必须保持辅助性质，避免“立即买入”“强烈推荐”等违规表达。

## 12. 推荐实施顺序

1. 数据库迁移：补字段、补字典。

9. 全量测试与合规文案扫描。

## 13. MVP 验收口径

完成后至少满足：

- 股票从市场页加入自选时，必须确认交易系统。
- 加入自选后进入观察中，并展示交易系统、关键观察价、失效条件。
- 系统只对观察中且启用扫描的自选股生成买入信号。
- 买点未确认时不允许用户确认买入。
- 买点确认后进入买入待确认。
- 用户确认买入必须填写止损位。
- 确认买入后进入交易中。
- MVP 只允许全部卖出。
- 全部卖出后生成待复盘任务。
- 放弃本次机会后，相同信号不会重复生成。
- 全流程无自动交易、无自动下单、无收益承诺。

### 14.6 交易确认改造

## 16. 最小可交付版本定义
